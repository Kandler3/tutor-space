# Требования безопасности TutorSpace

[Паспорт](../PROJECT.md) · [Угрозы](threat-model.md) · [Решения](design-decisions.md)

**Сейчас работают:** регистрация, вход, свой профиль, выход и проверка доступности БД. **Планируются:** связи, расписание и задания. Критерии ниже задают ожидаемые результаты; результаты запуска приведены в [README](../README.md).

## Предметные допущения

- Роль `tutor` или `student` выбирается при регистрации. Роль разрешает вид действия, но не доступ к любому объекту.
- Связь: приглашение репетитора → принятие учеником → прекращение любой стороной. Новые задания и бронирования требуют активной связи.
- Старые задания и занятия сохраняют исходных участников. Прекращение связи не отнимает у них доступ; новый репетитор не получает историю. Старое занятие отменяет только его ученик или репетитор.
- Ученик заменяет решение до проверки. После проверки текст и результат окончательны. Срок сдачи информационный, без автоматического запрета отправки.

## Требования и критерии приёмки

### SR-01

**Действующая сессия.** Сервер определяет пользователя по сессии, а не по ID или роли из запроса. После logout либо истечения 24 часов токен не даёт доступа новым запросам.

**Проверка:** токен A возвращает только профиль A. Без токена, с поддельным, изменённым, истёкшим или отозванным токеном — `401` без профиля. Подстановка чужого ID не меняет субъекта; неверный пароль не создаёт сессию.

**Статус:** сессии реализованы; предметные действия планируются. [T-01](threat-model.md#t-01), [T-07](threat-model.md#t-07) → [D-01](design-decisions.md#d-01).

### SR-02

**Хеши вместо секретов.** В БД нет открытых паролей и исходных токенов. Пароль — Argon2id с индивидуальной солью, токен — SHA-256 случайного значения. Это уменьшает последствия утечки БД, но не исключает перебор слабого пароля.

**Проверка в тестовой БД:** у одинаковых паролей разные хеши; профиль Argon2id — 19 MiB, 2 прохода, параллелизм 1, соль 16 байт. Сохранённый хеш токена совпадает с SHA-256 выданного токена; сам `token_hash` не принимается вместо токена (`401`). Исходных секретов в строках нет.

**Статус:** реализовано. [T-07](threat-model.md#t-07) → [D-01](design-decisions.md#d-01).

### SR-03

**Доступ к своему объекту.** Сервер проверяет роль и участие пользователя в конкретном задании или занятии. Автор и проверяющий определяются сервером. Списки также ограничены правами.

**Проверка:** создать независимые пары A/B. Чтение или изменение чужого объекта по известному ID — `404` без данных и изменений; чужих объектов нет в списке. Ученик не оценивает работу, репетитор не отправляет решение за ученика (`403`). Разрешённое действие со своим объектом успешно.

**Статус:** свой профиль реализован; предметная авторизация планируется. Основание — [OWASP ASVS 5.0.0, 8.2.2](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/en/0x17-V8-Authorization.md), без заявления о проверке всего ASVS. [T-02](threat-model.md#t-02), [T-03](threat-model.md#t-03), [T-05](threat-model.md#t-05) → [D-02](design-decisions.md#d-02).

### SR-04

**Согласие на связь и сохранение истории.** Приглашение не создаёт право до принятия приглашённым учеником. Прекращённая связь запрещает новые совместные действия; старые объекты доступны исходной паре.

**Проверка:** до принятия создание задания/бронирования — `403`. Чужой ученик не принимает приглашение (`404`, состояние прежнее). После принятия новые действия разрешены; после прекращения запрещены. Новый репетитор не видит старые работы, прежние участники сохраняют доступ и возможность отмены старого занятия.

**Статус:** план. [T-03](threat-model.md#t-03), [T-02](threat-model.md#t-02) → [D-02](design-decisions.md#d-02).

### SR-05

**Целостность расписания.** На интервал приходится максимум одно активное занятие. Повторная отмена X не освобождает интервал нового занятия Y. Интервалы одного репетитора не пересекаются; `start < end`, общая граница допустима.

**Проверка:** два ученика одновременно бронируют интервал через два процесса API с общей БД — один успех, один `409`, одна активная запись. Отменить X, создать Y, повторить отмену X: Y остаётся активным. Чужая отмена — `404` без изменений. Из двух конкурентных пересекающихся интервалов сохраняется один; соседние допустимы.

**Статус:** план. [T-04](threat-model.md#t-04) → [D-03](design-decisions.md#d-03); права отмены — [D-02](design-decisions.md#d-02).

### SR-06

**Оценка относится к просмотренному тексту.** Решение отправляет назначенный ученик, проверяет выдавший задание репетитор. Оценка привязана к серверной ревизии, которую он прочитал. После проверки текст и результат не меняются; клиент не назначает автора, статус или оценку за ученика.

**Проверка:** репетитор читает v1, ученик сохраняет v2. Оценка с ревизией v1 — `409` без изменений; после чтения v2 оценка её ревизии успешна. Отправка v3 после проверки — `409`. При конкуренции: либо отправка первой меняет ревизию и отклоняет старую оценку, либо оценка первой запрещает отправку. Чужой участник — `404`, лишние серверные поля отклоняются.

**Статус:** план. [T-05](threat-model.md#t-05) → [D-02](design-decisions.md#d-02), [D-03](design-decisions.md#d-03).

### SR-07

**Однозначный ввод и параметризованный SQL.** Клиент передаёт значения, а не SQL-код или произвольные поля состояния. Ошибочный ввод отклоняется до записи.

**Проверка:** SQL-фрагмент в допустимом текстовом поле остаётся текстом, посторонние строки не меняются. Недопустимые логин/ID отклоняются. Тело свыше 4096 байт, неизвестные/повторные/неверно регистрированные ключи, лишний JSON и некорректный UTF-8 — 4xx без новой записи. Логин: `[a-z0-9_]{3,32}`; имя: 1–80 Unicode-символов без управляющих после удаления крайних пробелов; пароль: 12–128 байт UTF-8, пробелы сохраняются. Для будущих текстов предел задаётся отдельно и проверяется на границе.

**Статус:** ввод и SQL пользователей реализованы; остальные команды планируются. [T-06](threat-model.md#t-06), [T-08](threat-model.md#t-08), [T-05](threat-model.md#t-05) → [D-03](design-decisions.md#d-03).

### SR-08

**Секреты не раскрываются.** Ответы, логи и публичные файлы не содержат пароль, сохранённые хеши, DSN или Authorization. Исходный токен выдаётся только клиенту при успешном входе.

**Проверка с тестовыми маркерами:** регистрация, вход, профиль, выход, ошибочные запросы и недоступная БД не раскрывают секреты в ответах, stdout/stderr и Git-файлах. Ошибка БД общая, без SQL/DSN. Учебные настройки `.env.example` не используются во внешних системах. Вывод токена API-клиентом контролирует оператор.

**Статус:** правило текущих и будущих обработчиков. [T-07](threat-model.md#t-07) → [D-01](design-decisions.md#d-01), [D-03](design-decisions.md#d-03).

## Граница обещаний

Демонстрация — HTTP через loopback на доверенном хосте с тестовыми данными. Для внешней сети нужны TLS, ограничение попыток входа и проверка конфигурации. Злонамеренный владелец хоста/БД вне модели.
