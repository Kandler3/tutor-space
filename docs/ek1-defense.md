ЕК1 — концепция безопасности и запускаемая основа. Слот около шести минут на команду, презентация не требуется. [Регламент](https://github.com/hse-rbpo-bachelor-2026/course/blob/e7ec47288ca9f7bc59dab3f4f8d52a1bef7d67b1/assessment/EK1.md).

## Личная проверка перед записью вклада

[Объяснение M1](../CONTRIBUTIONS.md#m1), [сообщённый M1 разбор M2](../CONTRIBUTIONS.md#m2) и [проверки Codex](../CONTRIBUTIONS.md#проверки-с-ии) уже записаны. Ниже — подготовка к самостоятельным ответам и команды для воспроизведения; новые результаты записываются с фактическим исполнителем.

**M1:** найти в [API](../internal/api/server.go), [сессиях](../internal/auth/session.go) и [SQL](../internal/store/store.go) проверку субъекта, срока и logout. Объяснить два варианта D-01, цену зависимости от БД и контрпример D-03.

**M2:** найти в [разборе ввода](../internal/api/input.go) ограничение тела и отказ лишним полям. Пройти SR-03/SR-04/D-02: чужой ID, согласие на связь, старые работы. Объяснить D-01 и v1/v2 в D-03, `409` без изменений и оба порядка конкурентных записей.

При запущенном Docker — первый терминал:

```sh
./scripts/run-local.sh
```

Второй терминал:

```sh
python3 scripts/smoke.py
curl -i 'http://127.0.0.1:8080/api/me?user_id=another_user'
curl -i http://127.0.0.1:8080/api/register \
  -H 'Content-Type: application/json' \
  -d '{"login":"ek1_m2_check","password":"LocalDemoPassword123!","name":"Учебная проверка","role":"student","student_id":"another_user"}'
```

Ожидается успешный smoke, затем `401` без профиля и `400 invalid_json`. Это проверка текущего API, а не авторизации будущих заданий. Команды тестов с отдельной PostgreSQL — в [README](../README.md#проверки-исходного-кода).

| Время | Кто | Содержание |

Это ориентир; адресный вопрос может получить любой участник. Для личных 10 нужны вся база и личное подтверждение обоих повышенных уровней; для 9 — базы и одного. Отдельный контрпример каждому не требуется, понимание — требуется.

## Вопросы для самопроверки

| Вопрос | Короткий ответ |
| --- | --- |
| Почему блокировки недостаточно? | Она защищает текущую запись, но не прежнее чтение v1 |
| Что такое `expected_revision`? | Условие сравнения с серверной ревизией, не её новое значение |
| Что проверяют барьеры? | Порядок v1/v2 и два порядка записи; после отказа сверяется БД |
| Зачем JWT состояние `sid`? | Подпись и срок не сообщают о logout |
| Почему выбран случайный токен? | Проще при уже нужной БД; цена — зависимость защищённого запроса от неё |
| Когда менять выбор? | При автономных сервисах, пересмотрев окно отзыва или способ его распространения |
| Почему нет доступа к старой истории у нового репетитора? | Объект сохраняет исходных участников |
| Что не испытано? | Предметные модули, два OS-процесса, остановка всей БД и внешнее размещение |
| Что делает Argon2? | Замедляет офлайн-перебор; два слота ограничивают память, не число попыток |
| Как объяснить вклад? | Назвать материал, своё действие, вывод/исправление и ссылку |
