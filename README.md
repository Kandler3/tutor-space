# TutorSpace

Учебный API для организации занятий и домашних заданий. Текущая версия подготовлена для **ЕК1**: работает основа пользователей, а предметные сценарии бронирования и домашних заданий ещё планируются. Полный продукт к этой контрольной точке не требуется.

## Что запускается сейчас

| Запрос | Результат |
| --- | --- |
| `GET /healthz` | Процесс HTTP-сервера отвечает |
| `GET /readyz` | Проверка соединения с PostgreSQL и наличия таблиц `users` и `sessions` |
| `POST /api/register` | Создание учебного пользователя с ролью `student` или `tutor` |
| `POST /api/login` | Вход и выдача непрозрачного токена сессии на 24 часа |
| `GET /api/me` | Профиль пользователя, определённого по сессии |
| `POST /api/logout` | Отзыв текущей сессии |

Логин: 3–32 строчных ASCII-символа `[a-z0-9_]`. Имя: 1–80 символов Unicode без управляющих символов; крайние пробелы удаляются. Пароль: 12–128 байт UTF-8; пробелы сохраняются. JSON-тело ограничено 4096 байтами; неизвестные и повторные поля, неверный регистр имён полей, некорректный UTF-8 и данные после первого JSON-объекта отклоняются. Пароли и токены не возвращаются в профиле: пароль хранится как Argon2id-хеш, токен — как SHA-256-хеш в таблице сессий. В каждом экземпляре API одновременно выполняются максимум два дорогих вычисления хеша; при занятых слотах регистрация/вход возвращают `503 authentication_busy` и `Retry-After: 1`.

## Локальный запуск

Нужны **Go 1.26 или новее**, Docker с Docker Compose и `curl`. Для автоматической проверки также нужен Python 3 со стандартной библиотекой. Docker используется только для локальной PostgreSQL; сервер запускается через Go.

Быстрый запуск из корня репозитория, когда Docker уже запущен:

```sh
./scripts/run-local.sh
```

Скрипт создаёт `.env` из учебного примера, если файла ещё нет, поднимает БД, применяет миграции и запускает сервер. Если образ БД уже есть локально, используется сохранённый образ без обращения к Docker Hub; для первого скачивания нужен интернет. Во втором терминале выполните `python3 scripts/smoke.py`; ожидаются строки `OK` и итоговое сообщение `EK1 foundation smoke check passed`. Остановка сервера — `Ctrl+C`; остановка учебной БД — `docker compose down`.

Те же действия по отдельности:

В корне репозитория:

```sh
if [ ! -f .env ]; then cp .env.example .env; fi
set -a
. ./.env
set +a
docker compose up -d --wait db
go run ./cmd/migrate
go run ./cmd/server
```

`.env.example` содержит учебные настройки локального окружения. База по умолчанию доступна на `127.0.0.1:55432`, API — на `127.0.0.1:8080`. Если порт БД занят, согласованно измените `POSTGRES_PORT` и порт в `DATABASE_URL` в `.env`; для занятого порта API измените `HTTP_ADDR`. `.env` исключён из Git. Для запуска в другом терминале снова загрузите его переменные командами `set -a`, `. ./.env`, `set +a`.

Миграция создаёт таблицы пользователей и сессий. Её повторный запуск безопасен: уже применённые версии goose не выполняет повторно. При недоступной БД команды запуска или миграции завершаются с ошибкой.

Проверьте во втором терминале:

```sh
curl -i http://127.0.0.1:8080/healthz
curl -i http://127.0.0.1:8080/readyz
python3 scripts/smoke.py
```

Ожидаемый результат: оба запроса возвращают HTTP 200, а скрипт печатает `OK` для регистрации, входа, собственного профиля, отказа без сессии и выхода. Скрипт создаёт пользователя с уникальным учебным логином; повторный запуск не требует очищать БД.

### Ручная проверка

```sh
curl -i http://127.0.0.1:8080/api/register \
  -H 'Content-Type: application/json' \
  -d '{"login":"demo_student","password":"LocalDemoPassword123!","name":"Учебный ученик","role":"student"}'

LOGIN_RESPONSE=$(curl --fail-with-body -s http://127.0.0.1:8080/api/login \
  -H 'Content-Type: application/json' \
  -d '{"login":"demo_student","password":"LocalDemoPassword123!"}')
SESSION_TOKEN=$(printf '%s' "$LOGIN_RESPONSE" | python3 -c 'import json, sys; print(json.load(sys.stdin)["token"])')
```

Регистрация возвращает HTTP 201 и профиль; повторная регистрация того же логина — HTTP 409. Вход возвращает `token`, `token_type`, `expires_at` и профиль; команда выше сохраняет выданный токен в `SESSION_TOKEN`. Следующие команды выполняются в том же терминале:

```sh
curl -i http://127.0.0.1:8080/api/me -H "Authorization: Bearer $SESSION_TOKEN"
curl -i http://127.0.0.1:8080/api/me
curl -i -X POST http://127.0.0.1:8080/api/logout -H "Authorization: Bearer $SESSION_TOKEN"
curl -i http://127.0.0.1:8080/api/me -H "Authorization: Bearer $SESSION_TOKEN"
unset SESSION_TOKEN LOGIN_RESPONSE
```

Ожидаемые статусы: **200, 401, 204, 401**. `/api/me` не принимает ID пользователя как основание доступа: личность берётся из проверенной сессии.

### Сохранение данных после перезапуска

Зарегистрируйте учебного пользователя, остановите сервер `Ctrl+C` и снова выполните `go run ./cmd/server`. Вход с теми же данными и `/api/me` должны вернуть тот же ID. После `docker compose down` и повторного `up` данные также сохраняются в именованном томе. Не добавляйте `-v` к `down`, если хотите сохранить данные.

### Запуск без Docker

Можно использовать отдельную локальную PostgreSQL и учебную БД, доступные вашей команде. Сначала настройте в `.env` пользователя, пароль, порт и `DATABASE_URL` для существующей локальной БД, затем загрузите конфигурацию:

```sh
set -a
. ./.env
set +a
go run ./cmd/migrate
go run ./cmd/server
```

Учебный пример `.env.example` задаёт конкретное подключение к `tutorspace` на `127.0.0.1:55432`; без Docker создание роли и БД выполняется средствами вашей PostgreSQL. `sslmode=disable` и HTTP предназначены для проверки на одной машине. Эта версия не предназначена для публикации API в сети: для такого запуска потребуются TLS и отдельная настройка окружения.

## Проверки исходного кода

```sh
go test ./...
go vet ./...
```

Для тестов с настоящей БД используйте **отдельную пустую учебную БД**, не содержащую нужных данных. При запущенной БД из Compose создайте `tutorspace_test` один раз:

```sh
docker compose exec -T db sh -c 'createdb -U "$POSTGRES_USER" tutorspace_test'
```

Если эта тестовая БД уже существует, повторять создание не нужно. Загрузите `.env` и получите адрес тестовой БД из текущего подключения, сохранив остальные параметры:

```sh
set -a
. ./.env
set +a
TEST_DATABASE_URL=$(python3 -c 'import os; from urllib.parse import urlsplit, urlunsplit; p = urlsplit(os.environ["DATABASE_URL"]); print(urlunsplit(p._replace(path="/tutorspace_test")))')
TEST_DATABASE_URL="$TEST_DATABASE_URL" go test -race ./...
unset TEST_DATABASE_URL
```

При PostgreSQL без Docker предварительно создайте отдельную БД `tutorspace_test` на том же сервере и предоставьте пользователю из `DATABASE_URL` права на неё.

Без `TEST_DATABASE_URL` проверки, которым нужна БД, пропускаются. Наличие успешной проверки основы не подтверждает будущие механизмы бронирования и домашних заданий.

Проверка помощником 3 октября 2026 года: PostgreSQL 16 в указанном Compose, повторное применение миграций, тесты с реальной БД и `-race`, `go vet`, `scripts/smoke.py` и остановка/повторный запуск процесса. Регистрация, профиль и существующая сессия сохранились после перезапуска; выход отозвал токен. Это результаты проверки подготовленной версии помощником, а не подтверждение личной проверки участников.

В `TestIntegrationAuthenticationLifecycle` также проверены два независимых экземпляра обработчика API с отдельными пулами к одной тестовой БД: сессия принимается обоими, после выхода через первый второй возвращает `401`. При закрытом пуле второй возвращает `500` без профиля. Это проверка общего серверного состояния; испытание остановки всей БД и двух отдельных OS-процессов остаётся в плане D-01.

Повторная проверка Codex по поручению M1 4 октября 2026 года: запуск, повторные миграции, HTTP smoke, `go test -race -count=1 ./...` с отдельной PostgreSQL и `go vet ./...` прошли. Отрицательные запросы из памятки вернули `401 unauthorized` и `400 invalid_json`; после перезапуска процесса сохранились профиль и действующая сессия, последующий logout отозвал токен.
